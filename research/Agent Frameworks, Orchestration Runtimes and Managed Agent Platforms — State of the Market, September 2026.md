## 4. Narrative: trends, the "which framework" debate, and recommendations

### 4.1 The architectural convergence of 2026: everything became a graph with a harness

Three of the four biggest vendor frameworks now share the same shape. Google's ADK 2.0 explicitly "transitions ADK from a hierarchical agent executor to a graph-based execution engine" where agents, tools and functions are nodes and the engine owns scheduling, routing, graph state, retries and HITL pauses ([adk.dev/2.0](https://adk.dev/2.0/)). Microsoft Agent Framework pairs stateful agents with graph-based Workflows that support checkpointing, time travel and human-in-the-loop ([Microsoft Tech Community](https://techcommunity.microsoft.com/blog/azuredevcommunityblog/the-future-of-agentic-ai-inside-microsoft-agent-framework-1-0/4510698), [GitHub](https://github.com/microsoft/agent-framework)). LangGraph has been that from the start and now markets durable execution as the headline feature ([GitHub](https://github.com/langchain-ai/langgraph)). Even CrewAI, the role-based outlier, added event-driven Flows with fine-grained execution control alongside its Crews ([GitHub](https://github.com/crewaiinc/crewai)).

The second convergence is the **agent harness**: an opinionated, batteries-included loop with filesystem, shell, memory, planning/todo modes, context compaction and tool approval. OpenAI shipped a "model-native harness" with native sandbox execution, a `Manifest` workspace abstraction and snapshot/rehydration checkpointing in April 2026 ([OpenAI](https://openai.com/index/the-next-evolution-of-the-agents-sdk/)). Microsoft's harness — function invocation, per-call history persistence, context compaction, planning with plan/execute modes, file memory, skills, web search, tool approval and OpenTelemetry, all on by default and individually removable — reached stable release at Build 2026 ([InfoQ](https://www.infoq.com/news/2026/08/agent-framework-harness-ga/)). AWS turned the harness itself into a managed service in June 2026, with configuration-defined agents that can be exported to Strands code via one CLI command ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-bedrock-agentcore-harness-generally-available/)). Pydantic AI ships a Harness and composes coding agents from reusable capabilities ([GitHub](https://github.com/pydantic/pydantic-ai)); Mastra documents a general-purpose harness with workspace, shell tools, memory and schedules ([Mastra docs](https://mastra.ai/docs)); Strands added a separate `harness-sdk` repo ([GitHub org](https://github.com/strands-agents)). "Harness engineering" is even a topic tag on the Pydantic AI repo ([GitHub](https://github.com/pydantic/pydantic-ai)).

The third convergence is **durability by delegation**. Rather than each framework building its own persistence layer, the 2026 pattern is to wrap the agent loop in a general durable-execution engine. Pydantic AI is the clearest example: first-party, co-maintained durable execution for Temporal, DBOS, Prefect and Restate, where with `TemporalDurability` "every model and tool call becomes a durable activity" and runs "survive restarts, failures, and long waits" ([GitHub](https://github.com/pydantic/pydantic-ai)). DBOS documents durable wrappers for the OpenAI Agents SDK, Google ADK, LlamaIndex (`DBOSRuntime`) and Vercel AI ([DBOS docs](https://docs.dbos.dev/ai/ai-quickstart)). Temporal has a public-preview OpenAI Agents SDK integration ([GitHub](https://github.com/temporalio/sdk-python)) and a Google ADK integration that makes LLM calls and tool executions Activities with automatic retries ([Temporal Replay 2026](https://temporal.io/blog/replay-2026-product-announcements)). LlamaIndex's `llama-agents` even enforces workflow concurrency through DBOS worker queues ([GitHub](https://github.com/run-llama/llama-agents)).

### 4.2 Consolidation in 2025–2026

- **AutoGen + Semantic Kernel → Microsoft Agent Framework.** Announced 2 Oct 2025 by AutoGen maintainer Eric Zhu; AutoGen (then 50.4k stars, 98 releases, 559 contributors) keeps a stable API with critical bug fixes and security patches but no significant new features ([AutoGen discussion #7066](https://github.com/microsoft/autogen/discussions/7066)). MAF 1.0 GA landed simultaneously for Python and .NET on 3 Apr 2026, Microsoft publishes migration guides and assistants for both predecessors, and committed to maintaining Semantic Kernel v1.x with bug/security fixes for at least one year after GA ([LangChain](https://www.langchain.com/resources/ai-agent-frameworks), [Praesidia](https://praesidia.ai/blog/microsoft-agent-framework-autogen-semantic-kernel-governance)). By 2026 AutoGen is characterised as in maintenance mode, with the community fork **AG2** carrying the original lineage — and AG2 still present as a first-class template on Vertex AI Agent Engine ([gravity.fast tracker](https://gravity.fast/blog/ai-agent-market-consolidation-watch-2026/), [Google Cloud](https://docs.cloud.google.com/agent-builder/agent-engine/develop/overview)). The framing is explicit: "fewer moving frameworks, clearer defaults, and supported upgrade paths" ([The Agent Ecosystem](https://www.theagentecosystem.com/blog/agent-framework-consolidation-2026)).
- **LangChain 1.0 / LangGraph 1.0 split of concerns.** LangChain became the high-level, provider-agnostic agent framework with `create_agent` and middleware, built on the LangGraph runtime; LangGraph remained the lower-level graph runtime for custom, long-running, production agents ([LangChain blog](https://www.langchain.com/blog/langchain-langgraph-1dot0)). The commercial layer was renamed from LangGraph Platform to LangSmith Deployment in October 2025 ([LangChain](https://www.langchain.com/langgraph-platform)), and LangSmith now positions as framework-agnostic across LangChain, LangGraph, Deep Agents, OpenAI Agents SDK, Microsoft Agent Framework, Mastra and custom code ([LangChain](https://www.langchain.com/resources/ai-agent-frameworks)).
- **Scope narrowing and deprecations.** LlamaIndex deprecated the TypeScript `workflows-ts` package and redirected users to the actively maintained Python Workflows in `llama-agents` ([LangChain](https://www.langchain.com/resources/ai-agent-frameworks)). Analysts characterise the framework/infrastructure layer as contracting through "talent absorption into platform owners, product narrowing, and frameworks entering maintenance mode" ([gravity.fast](https://gravity.fast/blog/ai-agent-market-consolidation-watch-2026/)).
- **M&A.** NICE acquired Cognigy for ~$955M (announced July 2025, closed 8 Sep 2025) ([gravity.fast](https://gravity.fast/blog/ai-agent-market-consolidation-watch-2026/)). Google paid $2.4B in July 2025 to hire Windsurf's CEO and co-founder into DeepMind plus a non-exclusive licence, after OpenAI's ~$3B acquisition attempt collapsed over Microsoft IP-access concerns; Cognition then acquired the remaining Windsurf assets ([AgentMarketCap](https://agentmarketcap.ai/blog/2026/04/09/ai-agent-ma-acceleration-q2-2026-google-windsurf-aws-adept)). Amazon acqui-hired Adept's leadership in June 2024 and stood up the Amazon AGI SF Lab under David Luan in December 2024 ([AgentMarketCap](https://agentmarketcap.ai/blog/2026/04/09/ai-agent-ma-acceleration-q2-2026-google-windsurf-aws-adept), [gravity.fast](https://gravity.fast/blog/ai-agent-market-consolidation-watch-2026/)). Salesforce completed 12+ acquisitions worth more than $10B in 2025 to build Agentforce, including Convergence.ai and Qualified ([AgentMarketCap](https://agentmarketcap.ai/blog/2026/04/09/ai-agent-ma-acceleration-q2-2026-google-windsurf-aws-adept)). Disclosed AI M&A transactions rose 155% in H1 2025, with at least 33 major acquisitions worth $157B+ and an average 25.8× AI revenue multiple ([AgentMarketCap](https://agentmarketcap.ai/blog/2026/04/09/ai-agent-ma-acceleration-q2-2026-google-windsurf-aws-adept)).
- **Protocols as the interop layer.** MCP is near-universal in this cohort; A2A is the newer axis — donated by Google Cloud to the Linux Foundation in June 2025 ([Google Cloud](https://docs.cloud.google.com/agent-builder/agent-engine/develop/overview)), shipped in AgentCore Runtime at GA ([AWS](https://aws.amazon.com/about-aws/whats-new/2025/10/amazon-bedrock-agentcore-available/)), exposed natively by LangSmith Deployment ([LangChain](https://www.langchain.com/langgraph-platform)), available as interfaces in Agno ([GitHub](https://github.com/agno-agi/agno)) and CrewAI ([changelog](https://docs.crewai.com/en/changelog)), and still maturing at Microsoft via a beta adapter ([LangChain](https://www.langchain.com/resources/ai-agent-frameworks)).

### 4.3 The "which framework for enterprise" debate, and the thin-framework counter-argument

**The thin/no-framework case is now the mainstream expert position.** Anthropic's guidance remains the anchor: start with the simplest thing, "start by using LLM APIs directly", and if you use a framework "make sure you understand the underlying code", because frameworks "often create extra layers of abstraction" that obscure prompts and responses, make debugging harder and tempt teams into unnecessary complexity — incorrect assumptions about what is under the hood are "a common source of customer error"; the recommendation is to reduce abstraction layers as a system moves to production ([Anthropic](https://www.anthropic.com/engineering/building-effective-agents)).

HumanLayer's **12-factor agents** goes further from field experience: after trying plug-and-play frameworks (Crew, LangChain), minimalist ones (smolagents) and "production grade" ones (LangGraph, Griptape), the author reports not seeing many frameworks in production customer-facing agents, observes that strong founders are "rolling the stack themselves", and argues good agents are "comprised of mostly just software" rather than a prompt-plus-tools-plus-loop ([12-factor agents](https://github.com/humanlayer/12-factor-agents)).

The 2026 vintage of this argument is blunter: production agents are "almost always simple orchestration written in plain code" — "You don't need a DAG library for that. You need a while loop and some error handling" — and adopting a framework means "betting that its authors understood your problem better than you do", a bet that in a fast-moving domain "almost never" pays off; the closing advice is to "write boring code that works" and adopt a framework only when plain code becomes genuinely painful and you can name the problem it solves ([Jia Wei Ng](https://jiaweing.com/blog/frameworks-are-where-agents-go-to-die)). A practitioner postmortem on LangGraph reaches the same conclusion from the opposite direction: LangGraph is "well-built software" that "earns its place" for genuinely complex multi-agent workflows, but "most small LLM applications don't need a state graph framework" — start with plain functions and dependency injection and add a framework when coordination complexity exceeds what straightforward code can express ([dev.to](https://dev.to/deadlocker/why-i-stopped-using-langgraph-4jo2)).

**But the quantitative evidence says topology, not the framework, is the real tax.** A 2026 benchmark of four harnesses (thin ~100-line loop, prebuilt `langgraph_react`, Claude SDK, custom LangGraph graph) on Claude Sonnet 4.6 found quality identical within single-trial noise (10/10 for thin and `langgraph_react`), while cost and latency spread by ~3×. Decomposed: the LangGraph "framework tax" was **1.42× thin**, but the custom planner/router/executor/reflector topology added **2.12× on top**, for **3.01× total**. The mechanism was measurable — 5.3 `read_file` calls per run for the custom graph vs 2.3 for thin and `langgraph_react` — because planner, reflector and finalizer each rebuilt their own message list and re-read files to re-establish context. The author's qualified recommendation: prefer thinner topologies; a framework layer under a thin topology may be relatively cheap ([Hien Luu](https://hien-luu.medium.com/thin-vs-thick-ai-agent-harnesses-0276ee0a8353)).

**Manus adds the context-engineering lens.** Manus deliberately built on frontier-model in-context learning rather than training end-to-end agentic models, to ship improvements "in hours instead of weeks" and stay "orthogonal to the underlying models" — "we want Manus to be the boat, not the pillar stuck to the seabed." They rebuilt their agent framework four times, call their process "Stochastic Graduate Descent", and name KV-cache hit rate as "the single most important metric for a production-stage AI agent." They also warn against dynamically adding/removing tools mid-iteration because it invalidates the KV-cache and can cause schema violations or hallucinated actions, and note MCP's popularity "adds fuel to the fire" by letting hundreds of unfamiliar tools into the action space ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)).

**The pro-framework enterprise case rests on governance, not capability.** Vendor-aligned analysis argues Microsoft Agent Framework is the enterprise-first choice because it collapses two lineages into one versioned 1.0 SDK with a stated migration path, session-based state, type safety, middleware hooks for auth/logging/guardrails, telemetry and graph-based orchestration — framed as "maintaining a research-flavored library" versus "building on a versioned 1.0 SDK" ([The Agent Ecosystem](https://www.theagentecosystem.com/blog/agent-framework-consolidation-2026)). LangChain's own guidance recommends its ecosystem when you need rapid multi-provider prototyping plus LangGraph for stateful orchestration, Deep Agents for long-running work and LangSmith for lifecycle observability ([LangChain](https://www.langchain.com/resources/ai-agent-frameworks)). And adoption data shows frameworks winning on the ground regardless of the discourse: **68% of new agent projects in 2026 start with a dedicated framework, up from under 30% in early 2024**, with category downloads up 340% YoY in 2025 ([AgentMarketCap](https://agentmarketcap.ai/blog/2026/04/07/langgraph-crewai-autogen-enterprise-framework-adoption-split)).

**The failure data reconciles both camps:** the most common buyer mistake is choosing a framework before defining the use case, and **41% of failed projects** are attributed to exactly that; LLM inference costs are underestimated by an average of **180%**; and cutting observability tools like LangSmith or LangFuse to save money is called out as non-optional risk ([Agentlist 2026 report](https://agentlist.directory/report-2026)).

### 4.4 Recommendations for enterprise agentic applications

1. **Decide the topology before the framework.** The measured cost driver was topology (2.12× on top of the framework's 1.42×), and 41% of failed projects chose a framework before scoping the system ([Hien Luu](https://hien-luu.medium.com/thin-vs-thick-ai-agent-harnesses-0276ee0a8353), [Agentlist](https://agentlist.directory/report-2026)). Start with the thinnest loop that passes your evals and add nodes only when they demonstrably improve outcomes ([Anthropic](https://www.anthropic.com/engineering/building-effective-agents)).
2. **Separate the agent loop from the durability substrate.** The 2026 best practice is a thin/typed agent library over a general durable-execution engine: Pydantic AI + Temporal/DBOS/Restate/Prefect ([Pydantic AI](https://github.com/pydantic/pydantic-ai)), OpenAI Agents SDK or Google ADK + DBOS or Temporal ([DBOS docs](https://docs.dbos.dev/ai/ai-quickstart), [Temporal](https://temporal.io/blog/replay-2026-product-announcements)), or LangGraph's built-in checkpointers if you accept its runtime ([GitHub](https://github.com/langchain-ai/langgraph)). This keeps recovery semantics (journaling, memoized replay, exactly-once side effects) out of your prompt-engineering iteration loop ([Inngest docs](https://www.inngest.com/docs/learn/durable-agents), [Restate docs](https://docs.restate.dev/ai/patterns/durable-agents)).
3. **Match the framework to the existing platform commitment, not to benchmarks.** .NET/Azure estates get a single supported SDK with migration guides and OTel-by-default in MAF ([Praesidia](https://praesidia.ai/blog/microsoft-agent-framework-autogen-semantic-kernel-governance), [InfoQ](https://www.infoq.com/news/2026/08/agent-framework-harness-ga/)); GCP estates get ADK 2.0's graph runtime with one-command Cloud Run deploys and Agent Engine scaling ([GitHub](https://github.com/google/adk-python)); AWS estates get Strands plus a managed harness that exports to Strands code ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-bedrock-agentcore-harness-generally-available/)); polyglot/TypeScript product teams get Mastra ([GitHub](https://github.com/mastra-ai/mastra)); Python-first teams wanting typing discipline get Pydantic AI ([GitHub](https://github.com/pydantic/pydantic-ai)).
4. **Treat HITL and audit as selection criteria, not add-ons.** Regulated workflows need approval semantics that survive restarts — Restate's restart-from-prefix explicitly preserves prior human approvals ([Restate](https://restate.dev/blog/announcing-restate-1-6)); Temporal drives approvals via Signals/Updates with multi-day waits ([Temporal docs](https://docs.temporal.io/ai)); LangSmith Deployment and CrewAI both expose resume-after-HITL ([LangChain](https://www.langchain.com/langgraph-platform), [CrewAI changelog](https://docs.crewai.com/en/changelog)). Conversely, CrewAI's auditability is task-level only ([AgentMarketCap](https://agentmarketcap.ai/blog/2026/04/07/langgraph-crewai-autogen-enterprise-framework-adoption-split)) and AWS does not expose agent-decision lineage as a queryable graph ([3h4x](https://3h4x.github.io/tech/2026/06/13/bedrock-agentcore-lock-in)).
5. **Price the lock-in explicitly at the control plane.** On managed platforms the portable part is the data plane (MCP, A2A, model choice); the sticky parts are control plane, memory, identity vault and policy enforcement in the request hot path ([3h4x](https://3h4x.github.io/tech/2026/06/13/bedrock-agentcore-lock-in)). Prefer platforms that let you export to code (AgentCore → Strands, LangSmith Deployment accepting any framework) and avoid building compliance stories on preview APIs ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-bedrock-agentcore-harness-generally-available/), [LangChain](https://www.langchain.com/langgraph-platform), [3h4x](https://3h4x.github.io/tech/2026/06/13/bedrock-agentcore-lock-in)).
6. **Check licence shape before standardising.** Most of Group A is MIT or Apache-2.0, but Mastra's `ee/` code requires a paid enterprise licence for production ([GitHub](https://github.com/mastra-ai/mastra)) and the Inngest server/CLI is SSPL with delayed Apache-2.0 publication while only its SDKs are Apache-2.0 ([GitHub](https://github.com/inngest/inngest)).
7. **Budget for evals, observability and iteration.** Non-deterministic systems need test suites, success metrics and failure thresholds before a production decision can be made; inference cost underestimation averages 180% and production load can be an order of magnitude above development load ([Agentlist](https://agentlist.directory/report-2026)). Prefer stacks with OTel-native tracing (MAF, ADK Go, Agno, Strands, AgentCore) so you are not locked into one vendor's telemetry ([GitHub](https://github.com/microsoft/agent-framework), [ADK Go](https://developers.googleblog.com/adk-go-10-arrives/), [Agno](https://github.com/agno-agi/agno), [Strands](https://strandsagents.com/), [AWS](https://aws.amazon.com/about-aws/whats-new/2025/10/amazon-bedrock-agentcore-available/)).
8. **Treat agent-to-agent trust as a security boundary.** The CSA note on Google's own ADK repository automation shows a low-privilege public agent being prompt-injected into issuing a command that a high-privilege agent trusted, with an allow-list bypassable via `git` aliases/hooks and cloud service-account credentials in scope — a structural A2A trust-boundary failure, not a one-off bug ([Cloud Security Alliance](https://labs.cloudsecurityalliance.org/research/csa-research-note-google-adk-trustissues-agent-injection-202/)). Related: smolagents' `LocalPythonExecutor` is explicitly not a security sandbox ([GitHub](https://github.com/huggingface/smolagents)), and MAF's shell/file/looping capabilities emit warnings when enabled ([InfoQ](https://www.infoq.com/news/2026/08/agent-framework-harness-ga/)).

### 4.5 Notable gaps in the public record (as of 2026-09-12)

- Named enterprise adopters are published far less often than capability claims: only LangGraph, Mastra, LlamaIndex Workflows, OpenAI (Oscar Health), Strands (Amazon Ads), Restate, DBOS (Yutori) and CrewAI (aggregate Fortune 500 figure) had any cited adopters on fetched pages.
- A2A is claimed inconsistently: present in ADK, MAF hosting, CrewAI, Agno, Strands 1.0, AgentCore Runtime and LangSmith Deployment, but absent or unstated for OpenAI Agents SDK, Pydantic AI, Mastra, smolagents, Temporal, Inngest, Restate, DBOS and LlamaIndex on the pages fetched.
- Version provenance is genuinely ambiguous for Strands (repo v1.13.0/Oct 2025 vs changelog v1.55.0/Sep 2026) and Dapr Agents (docs say v1.0 GA, repo latest release v0.9.3/Oct 2025).
- Pricing is undisclosed on the official pages for Azure AI Foundry Agent Service and Vertex AI Agent Engine's develop-overview; Restate's licence type was not stated on any page fetched.
