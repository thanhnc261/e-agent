# Design-system review resolution

Date: 2026-10-10. [Claude's read-only review](CLAUDE-REVIEW.md) inspected source and three screenshots; it did not execute tests. Files were changing during the review, as the report records. This resolution describes the subsequent candidate changes; it is not a second Claude approval.

| Finding                                 | Resolution                                                                                                                                                                                                                                                                                                                                                                          |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Destructive hover loses contrast     | Explicit destructive hover retains the failed-role fill; generic hover specificity reduced. Added rendered hover checks in all three themes.                                                                                                                                                                                                                                        |
| 2. High-contrast badges lack boundaries | High-contrast badges now use a current-color border; forced-colors fallback remains. Added rendered border assertion.                                                                                                                                                                                                                                                               |
| 3. Component aliases bypassed           | Composer radius/padding, panel radius and primary/secondary/destructive button radius consume their component aliases. Chip removal consumes the minimum-target token. Motion tokens and base layer are used. Checks now require each component alias and key control tokens to be consumed. Foundation tokens may intentionally be catalog-only; there is no blanket ban on those. |
| 4. Navigation focus/state               | All navigation toggles expose expanded state and their sidebar relationship. Collapse/expand moves focus to the visible toggle. Browser checks cover desktop focus and state; the existing mobile Escape check remains.                                                                                                                                                             |
| 5. Tabpanel removed from tab order      | Removed the update-time `tabindex=-1` mutation. Added reject/refresh focus and tab-order checks across chat viewports.                                                                                                                                                                                                                                                              |
| 6. Focus geometry diverges              | Composition now uses the same focus-width/offset tokens as components.                                                                                                                                                                                                                                                                                                              |
| 7. Breakpoint drift                     | The build generates `MOBILE_QUERY` from the token and app logic uses `matchMedia`. Build checks bind the explicit CSS mobile/compact conditions to token values; CSS queries cannot use custom properties directly.                                                                                                                                                                 |
| 8. Native controls stay light           | Generated theme scopes now set `color-scheme`. Warm light remains the intentional default for this owner-requested study; automatic OS-theme selection is deferred to production preference precedence. The explicit theme selector/query works now.                                                                                                                                |
| 9. Inline icon fallback                 | Generated metrics supply inline SVG stroke attributes as well as exported SVGs. CSS may override the same token for theme/customization. Checks assert both representations match the source value.                                                                                                                                                                                 |
| 10. Message/composer width differs      | Both now consume the conversation-width token.                                                                                                                                                                                                                                                                                                                                      |
| 11. Dead CSS / read-back headings       | Removed unused trace, legacy status and text-action rules; read-back headings use the type scale.                                                                                                                                                                                                                                                                                   |
| 12. Shared tone colors                  | Intentional: review/unknown share caution color, and working/access-needed share an attention color. Each state retains a distinct label and icon; unknown still provides investigation rather than blind retry. High contrast now adds borders. No business status is inferred from color alone.                                                                                   |
| 13. Smaller inconsistencies             | Removed the initial source-search announcement, shared tab keyboard mechanics, limited native title hints to icon-only buttons, and documented in-flow disclosure. Shared study-03 fixtures/action records remain intentionally reused; serving the parent directory is documented.                                                                                                 |
| 14. Focus visible in screenshots        | The verification loop intentionally focuses tabs to test arrow/Home navigation before capture. Added a separate assertion immediately after starting a conversation: focus must be in the composer.                                                                                                                                                                                 |

Additional coverage now renders the full chat in forced-colors mode. The short catalog confirmation focuses Back; the longer chat review focuses its heading so the full context can be read. Both choices avoid initial focus on the consequential action. The catalog contract and frontend specification now state this distinction.

The initial new hover assertion sampled a theme transition before it settled. It now awaits active animations before comparing fills; this does not suppress hover behavior. All completion claims are based on the final checks recorded in [QA](../QA.md). Actual-device, screen-reader, zoom, embedded-host and production tests remain outstanding.
