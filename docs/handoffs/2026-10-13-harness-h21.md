## Codex review, round 1

A read-only Codex review of `main...HEAD` (harness and skills scope) returned nine findings, all confirmed and fixed test-first in one commit (18 new test cases, red then green):

1. **High:** the DSN comparison missed quoted keyword values, percent-encoding and `?dbname=` overrides. The guard now parses libpq URL and keyword forms, compares database names on any host, and refuses a DSN whose name cannot be read.
2. **High:** only the `pg` set was guarded, but `gate full` runs the run-store conformance tests, which use PostgreSQL whenever `E_AGENT_TEST_PG_DSN` is set. The separation guard is now a `"*"` guard on every set.
3. **High:** redaction kept `Authorization: Basic <credential>` and the tail of JSON strings with escaped quotes. Both are now fully redacted.
4. **High:** `add-feature ../../research …` wrote outside `harness/state`. Phase and task ids are now validated as single path components.
5. **High:** a task whose features did not pass could be "closed". `close-check` now requires every contracted feature to pass with valid evidence.
6. **High:** smoke (`quick`) evidence satisfied a `full` contract. Evidence must now be valid gate evidence from the contract's gate set.
7. **Medium:** a hook path with backslashes (`archive/..\src\x.py`, a real file name inside `archive` on POSIX) was normalised into an allowed path. Backslash paths are now denied.
8. **Medium:** a plain `refresh-task` cleared acceptance drift without re-deriving the acceptance. Only `--from-features` now renews the feature digest.
9. **Medium:** `status` named a close sequence that could not complete. It now walks the eng-session order: passes and evidence, handoff, checkpoint, bookkeeping commit, close-check.

## Codex review, round 2

The same Codex thread re-checked round 1: findings 2, 5, 6, 7 and 8 fixed; 1, 3, 4 and 9 partly fixed; each round-1 regression test fails without its fix. Six remaining findings, fixed test-first (8 new test cases, red then green):

1. **High:** libpq also unescapes backslashes in unquoted keyword values, keeps a literal `+` in URL queries, and an empty `?dbname=` cannot be compared. The parser now does all three; an empty override is refused.
2. **High:** a real `Authorization: Digest username=…, response=…` header kept its response, and `--password "two words"` kept the second word. Authorization values are redacted to the end of the line; flag values accept quoted strings.
3. **High:** a symlink inside `harness/state` (directory or destination file) could still send a write outside it. Every id-based state path is now checked after resolving symlinks.
4. **Medium:** after reopening a closed task, `status` treated a feature as done by its `passes` flag although its evidence no longer tied to HEAD. A feature now counts as done only when its referenced evidence is valid for this task, gate set and commit.
5. **Medium:** a checkpoint written during implementation satisfied the closing checkpoint. `close-check` and `status` now need a checkpoint after the gate evidence (timestamps are recorded to the microsecond), and `status --session <id>` judges it for the current session.
6. **Medium:** a contract made stale by an authoritative-file change could still close. `close-check` now rejects a stale contract.

Consequence on this branch: Phase 1's last task `1.R1` closed before H2.1 changed `AGENTS.md` and the plans, so `status` reports its contract as stale, and `close-check` also reports that its evidence (`evidence/gates/1.R1/…`, in the git-ignored legacy folder, present only in the main checkout) is missing here. A refresh alone does not re-close it. Two ways forward:

- Re-close `1.R1`: `refresh-task`; `gate full` on the clean tree (new evidence under `harness/state/evidence/`); point `F-1-R1` and the handoff's `evidence_refs` at the new evidence; `checkpoint`; commit the bookkeeping; `close-check`.
- Or start the next phase with `eng-phase-plan`; `new-task` for its first feature needs `--replace` while `1.R1` is open.

## Codex review, round 3

The same thread re-checked round 2: findings 1, 2, 4 and 6 fixed; 3 and 5 partly fixed. Five findings, fixed (4 new test cases red then green, one test corrected):

1. **High:** containment trusted the resolved `harness/state`, so a symlinked state directory passed, and `active.json`, `progress.md` and the live-evidence folder were not checked. The anchor is now the intended directory under the real repository root, and every state path is checked; the CLI reports such refusals instead of raising.
2. **Medium:** a checkpoint written while a gate was still running counted as "after the gate". Evidence now records `finished_at`, and the closing checkpoint must follow it (legacy evidence without it falls back to `started_at`).
3. **Medium:** `status` picked the newest evidence by comparing timestamp text. Evidence times are now compared as instants (`closecheck.newest`).
4. **Low:** the empty-`dbname` regression used a fallback name equal to the live one, so it passed without the fix. It now uses a different fallback name and expects "cannot tell"; it passes on this branch and would be allowed by the round-1 parser.
5. **Low:** this handoff claimed a refresh alone re-closes `1.R1`; corrected above.

## Codex review, round 4

The same thread re-checked round 3: findings 1, 3, 4 and 5 fixed, 2 partly. It also checked containment through a symlinked repository root, a worktree and a missing state directory, the PreToolUse, PreCompact and Stop exit codes, legacy evidence, and malformed timestamps, with no findings. Verdict: no Blocker; one High blocking the merge. Three findings, fixed (4 new tests red then green):

1. **High:** with `E_AGENT_HARNESS_UNATTENDED=1`, an invalid state (an escaping symlink, a corrupt `active.json`, malformed hook input) made the Stop hook exit 1, which does not block. The enabled Stop hook now fails closed with exit 2 and the reason on stderr; disabled and recursive Stop still exit 0.
2. **Medium:** `finished_at` was the start time plus the summed command durations, which omits setup and the time between commands, so a checkpoint during the gate could still count. It is now read from the clock when the last command has ended (injectable for tests).
3. **Low:** a lowercase `z` passed the schema but broke the evidence-time parser. One shared parser (`contracts.parse_timestamp`) now serves the schema check, evidence times and progress timestamps.

- `clean_tree` in gate evidence now means "no change outside harness bookkeeping"; `close-check` still requires a fully clean tree. Cost if wrong: evidence recorded with uncommitted bookkeeping counts as clean, which `close-check`'s ancestor rule already allows.
- The stale-digest remedy is now `refresh-task`, not `new-task --replace`; two old tests that asserted the old remedy and the old post-`new-task` message were updated to the fixed behaviour. Cost if wrong: none.
- The task schema checks the gate-set name shape instead of a fixed list; `new-task` checks the name against the manifest. Cost if wrong: none.
- The database guard compares names only, on any host: a test database must have a different name from the live ledger even on another server. Conservative by design. Cost if wrong: one rename of a test database.
